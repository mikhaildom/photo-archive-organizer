# Порядок в семейном фотоархиве

Семейный архив — это вещь, которую нельзя восстановить. Поэтому главное в этом скилле не скорость, а то, что после работы человек **ничего не потерял, всё может откатить и понимает, что где лежит**. Ты работаешь в чужих воспоминаниях: смотри сам, предлагай, а решает владелец.

## Пять правил, которые нельзя нарушать

1. **Сначала смотри, потом трогай.** Решение о снимке принимается только после того, как ты его увидел (лист миниатюр, сам файл). Имя файла и дата почти ничего не говорят о содержимом.
2. **Ничего не удаляй сам.** Удаление — только по явному «да» владельца на конкретный список, и только в Корзину (`scripts/to_trash.py`), никогда навсегда. Корзину не очищай.
3. **Каждое действие — через план, пробный прогон и журнал.** Переносы и переименования делает `scripts/apply_plan.py`: сначала без `--go` (проверка), потом с `--go`. Каждое действие записывается в журнал, по журналу всё откатывается (`--undo`).
4. **Новые папки и имена согласуй.** Покажи предлагаемые имена целиком и дождись «да». Отдельные мелкие решения («это же 8 Марта?») собирай в один список вопросов.
5. **Личное — бережно.** Документы, медицинские бумаги, паспорта, полисы, скриншоты переписок не открывай без разрешения. Номера документов никуда не выписывай. Если тема тяжёлая (болезнь, смерть), пиши коротко и мягко.

Подробно, почему каждое правило появилось — `references/lessons.md` (там реальные ошибки и как их избежать). Прочитай его перед первым переносом.

## Как идёт работа

### 1. Опись (только чтение)
```
python scripts/inventory.py "<папка архива>" --out work/inventory.csv
```
Даёт по каждому файлу: дату из EXIF, дату из имени, камеру, размер, отметку о подозрительной дате. Посмотри итог: сколько файлов, какие годы, какие камеры, где даты врут. Рабочие файлы (опись, листы, планы, журналы) держи в отдельной папке `work/` **вне** архива — в сам архив пиши только то, что владелец просил.

### 2. Смотри глазами
```
python scripts/contact_sheet.py "<папка>" --out work/sheets/<имя> --cols 6 --size 260
```
Листы миниатюр с подписями (имя файла и дата). Смотри каждую папку. Для каждой группы снимков определи:
- **что за событие** (день рождения, поездка, утренник, ремонт);
- **когда** — см. «Как восстановить дату»;
- **где** — см. «Как опознать место»;
- **кто** — только если владелец сам назвал людей; не угадывай имена.

Большой архив (тысячи файлов) дели на части и раздавай параллельным помощникам (subagents), каждому — свою пачку папок и одинаковую инструкцию «только читать, вернуть список: файл → событие → дата → уверенность».

### 3. Предложи план
Опиши владельцу словами, коротко, по пунктам:
- какие папки-события получатся (имена целиком, каждое — отдельной строкой, чтобы его можно было скопировать);
- что куда переносится;
- что, по-твоему, дубли (покажи пары рядом, а не имена);
- что не событие (документы, скриншоты, фоны) — что с этим делать, решает владелец;
- вопросы, без которых нельзя (один список).

Длинный разбор сохраняй в файл-отчёт (`work/Анализ — <папка>.md`), в чат — выжимку.

### 4. Выполни план
Запиши план в JSON (формат — в `references/plan-format.md`), затем:
```
python scripts/apply_plan.py work/plan-01.json --root "<архив>" --log work/журнал.txt         # проверка
python scripts/apply_plan.py work/plan-01.json --root "<архив>" --log work/журнал.txt --go    # выполнение
python scripts/apply_plan.py --undo work/журнал.txt --root "<архив>" --go                       # откат, если надо
```
Скрипт останавливается до начала, если хоть один источник не найден или цель уже существует — ничего не перезаписывает.

### 5. Отчитайся
- Что сделано — по пунктам, имена новых папок полностью.
- Что не сделано и почему, какие вопросы остались.
- Когда спрашивают «где это?» или «покажи» — присылай сам снимок, а не имя файла.

## Имена папок

Формат корня архива: `ГГГГ-ММ-ДД Описание`, по-человечески, на языке владельца.

| Случай | Пример |
|---|---|
| один день | `2012-02-25 Каток на стадионе` |
| несколько дней | `2012-02-17–18 Ледовый городок` |
| известен только месяц | `2015-09 Поход с классом` |
| период | `2014-08 – 2016-01 Ремонт квартиры` |
| поездка | `2019-09-09 Турция, Сиде, отель «Морской»` |

- Если внутри «сборной» папки (например, «Мамин телефон 2010–2016») делаешь подпапки-события — называй их **сразу в формате корня**, чтобы владелец мог потом просто вытащить их наверх.
- Голую дату без описания не оставляй. Папку, где смешаны разные дни и сюжеты, — дели.
- Если владелец уже придумал имя или свой формат — используй его, не «исправляй».
- Описание — что произошло, а не «Фото 1». Город и отель в имени — когда уверенность высокая.

## Как восстановить дату

Источники по надёжности (подробно и с ловушками — `references/dates.md`):
1. EXIF `DateTimeOriginal` с камеры, у которой часы были выставлены.
2. Имя файла: `IMG_20190914_214715`, `20151111_142659`, `IMG-20151115-WA0000` (у WhatsApp это дата **получения**, а не съёмки).
3. Соседние кадры той же камеры: номера идут подряд — значит и время рядом.
4. Содержимое: снег/листва, одежда, возраст ребёнка, вывески, календари, телевизор, реклама.

Ловушки: одинаковая дата у сотен снимков (часы телефона не выставлены — например, у всех `2006:08:02 00:00:00`); дата изменения файла после копирования; разные счётчики у одной камеры. `inventory.py` помечает такие даты флагом `suspicious_date` — не верь им.

## Как опознать место

- GPS в EXIF → адрес (обратное геокодирование).
- Вывески, логотипы на дверях, браслеты «всё включено», полотенца, бейджи, таблички номеров, бланки экскурсий.
- Характерные здания, памятники, набережные — сравни с фото в интернете, если есть доступ.
- Для отелей и поездок клади в папку короткую заметку `Отель.txt` / `Место.txt`: название, уверенность и почему, курорт, адрес, нынешнее название (отели часто переименовывают), ссылка-источник. Только если владелец согласен, что в папку архива можно добавлять файлы.

## Дубли

```
python scripts/find_duplicates.py "<папка>" --out work/dups.csv
```
- `exact` — байт в байт одинаковые: безопасные кандидаты.
- `same_picture` — та же картинка в другом размере, повороте или пересжатии: оставлять лучшую (больше разрешение, есть EXIF).
- **Серия похожих кадров — не дубли.** Соседние кадры одной сцены владелец обычно хочет сохранить.
- Перед удалением покажи пары листом миниатюр рядом и получи «да» на список. Потом `scripts/to_trash.py` (в Корзину).

## Чего не делать

- Не создавай файлы в архиве «для себя» (кэш, `.bak`, миниатюры, отчёты) — всё рабочее в `work/`.
- Не переименовывай исходные файлы массово «по шаблону» без просьбы: оригинальные имена (`DSC02479.JPG`) помогают найти снимок в других копиях.
- Не поворачивай и не пересохраняй JPEG без просьбы — это меняет файл и даты. Поворот делай средствами, не теряющими качество, и только по согласию.
- Не перемещай то, что лежит у владельца в «неприкосновенных» папках (спроси, есть ли такие).
- Не угадывай, кто на фото, и не пиши имена людей в названия без подтверждения.

## Скрипты

Нужен Python 3.9+ и Pillow (`pip install Pillow`). По желанию: `pillow-heif` (фото iPhone .HEIC), `send2trash` (Корзина на macOS/Linux).

| Скрипт | Что делает | Пишет в архив? |
|---|---|---|
| `inventory.py` | опись: даты, камеры, подозрительные даты | нет |
| `contact_sheet.py` | листы миниатюр с подписями | нет |
| `find_duplicates.py` | точные и визуальные дубли (с учётом поворота) | нет |
| `apply_plan.py` | папки, переносы, переименования, заметки по плану; журнал и откат | да, только с `--go` |
| `to_trash.py` | отправка списка файлов в Корзину | да, только с `--go` |
